# Releasing Local Sheets

Pushing a tag `vX.Y.Z` runs `.github/workflows/release.yml`: it builds the Windows and Linux
packages, writes `SHA256SUMS.txt` and publishes them on the GitHub Release of that tag. The
publish step is idempotent — re-running a tag whose release already exists replaces its assets —
and only runs when both build jobs passed. There is no `release` branch and no draft.

This process was copied from the upstream and rebranded. User-facing names say **Local Sheets**.
Files, binaries and ids stay lowercase (`localsheets-<version>-<platform>-<arch>.<ext>`,
`com.local.localsheets`).

| App-specific value | Where |
|---|---|
| Display name `Local Sheets`, binaries `localsheets` + `localsheets-cli` | every script and workflow |
| Bundle / app id `com.local.localsheets` | `packaging/macos/Info.plist.in`, `packaging/linux/*`, flatpak manifest |
| WiX UpgradeCode `55FDA4F8-0254-4A96-8AA0-3D6DA79AD606` (fixed forever) | `packaging/windows/localsheets.wxs` |
| File types `.xlsx` `.xlsm` `.xlsb` `.ods` `.csv` `.tsv` | Info.plist (`CFBundleDocumentTypes`), WiX (ProgIds/OpenWithProgids), `.desktop` `MimeType=`, `com.local.localsheets.mime.xml`, metainfo |
| Web app dir `apps/localsheets-web` | `packaging/web/package.sh` |
| App colour `#1f9d55` (ink `#147a40`), **proposed** | `assets/app-icon/README.md`, metainfo `<branding>` |

## Application release prerequisites

The `apps/localsheets` and `apps/localsheets-web` crates are workspace members, and
`apps/localsheets-cli` supports `--version`. The `cargo xtask` alias is defined in
`.cargo/config.toml`. The current app-specific release setup includes:

- **Windows resources:** `apps/localsheets/build.rs` embeds the icon and version information with
  `winresource` (instructions at the top of the file). `package.ps1` sets
  `LOCALSHEETS_REQUIRE_WINRES=1`, so a release build without the icon fails, and it checks that
  `localsheets.exe` is a GUI-subsystem binary. `apps/localsheets/src/main.rs` sets
  `windows_subsystem = "windows"` for release builds.
- **Version information:** `localsheets --version`, `localsheets-cli --version` and the About dialog
  use `env!("CARGO_PKG_VERSION")` from `[workspace.package]`. `packaging/env.sh` also exports
  `LOCALSHEETS_BUILD_SHA` and `LOCALSHEETS_BUILD_DATE` for artifact metadata.
- **Fonts:** the CI and release workflows check out `storytold/craft-fonts` at the pinned commit
  into `craft-fonts/` inside the workspace and export `CRAFT_FONTS_DIR`; without it the binary
  ships without the bundled fonts ("building without craft-fonts" in the log).
- **Runtime icon:** `apps/localsheets/src/main.rs` embeds
  `assets/app-icon/localsheets-macos-512.png` (macOS Dock) and
  `hicolor/256x256/apps/com.local.localsheets.png` (Windows/Linux) as the window icon, and
  uses `com.local.localsheets` as the Wayland app id / `StartupWMClass`.

## Cutting a release

1. **Bump the version** on `main`. The only place it lives is `[workspace.package] version`
   in the root `Cargo.toml`:

   ```sh
   cargo xtask version                 # prints the current version, e.g. 0.1.0
   cargo xtask version set 0.2.0       # or 0.2.0-rc.1; updates Cargo.toml and Cargo.lock
   ```

   Commit `Cargo.toml` + `Cargo.lock` and push. Bumping and tagging in separate pushes is fine;
   tagging **without** the bump is not — the assets are named from `Cargo.toml`, so the release
   would carry the previous version in every file name.
2. **Wait for CI** on that commit (`gh run list --workflow ci.yml`; several runs can reference the
   same SHA, so filter by workflow).
3. **Push the tag alone**, pointing at the verified commit:

   ```sh
   git tag v0.2.0 <sha> && git push origin v0.2.0
   ```

   Push one tag per push: pushing more than three tags at once does not create the events that
   start the workflow.
4. **Let it publish.** Both jobs must pass; the release appears with every artifact and
   `SHA256SUMS.txt`. `-rc.N` versions are marked as pre-releases.
5. **Moving an unpublished tag** is safe: `git tag -f v0.2.0 <sha>`, delete the remote tag
   (`git push origin :refs/tags/v0.2.0`) and push the tag again — the workflow runs from scratch.
   Once a release is published, bump instead.
6. **Add the parity delta** to the notes after publishing:
   `git diff v<previous> v<this> -- docs/parity-checklist.md` (regenerated by `cargo xtask parity`).

## What the release workflow builds

| Platform | Artifacts | Job |
|---|---|---|
| Windows 10+ x64 | `localsheets-<v>-windows-x64.msi` (per-machine), `localsheets-<v>-windows-user-x64.msi` (per-user), `localsheets-<v>-windows-x64-portable.zip` | `windows-latest` |
| Linux x86_64 | `localsheets-<v>-linux-x86_64.{AppImage,AppImage.zsync,deb,rpm,tar.gz}` | `ubuntu-22.04` |
| All | `SHA256SUMS.txt` | publish |

The other packagers in `packaging/` are run by hand, not by `release.yml`: macOS
(`packaging/macos/package.sh`), Windows x86/ARM64 (`package.ps1 -Arch`), FreeBSD
(`packaging/freebsd/package.sh`), Flatpak (`packaging/linux/flatpak*.sh`) and the web site
(`packaging/web/package.sh`).

### macOS

`packaging/macos/package.sh` builds `aarch64-apple-darwin` and `x86_64-apple-darwin` with
`MACOSX_DEPLOYMENT_TARGET=11.0`, joins them with `lipo`, and assembles `Local Sheets.app`:

- `Info.plist` comes from `Info.plist.in`: bundle id `com.local.localsheets`,
  `LSMinimumSystemVersion` 11.0, `NSHighResolutionCapable`, category productivity, and
  `CFBundleDocumentTypes` for `.xlsx`, `.xlsm`, `.xlsb`, `.ods`, `.csv` and `.tsv` with rank
  **Alternate**, so Local Sheets is offered in *Open With* without taking over Numbers' (or another
  app's) defaults. `.xlsm` and `.xlsb` get imported UTIs in case macOS doesn't know them.
- **Signing** goes inside-out with the hardened runtime and a secure timestamp; no `--deep` on
  the final signature; `entitlements.plist` is deliberately empty.
- **Notarization:** the app is zipped and sent with `xcrun notarytool submit --wait`, then
  stapled. The DMG (with an `Applications` link) is signed, notarized and stapled too, and
  checked with `codesign --verify --strict`, `stapler validate` and `spctl -a -vvv`.
  Its Finder window (background, icon size and positions) comes from
  [`packaging/macos/dmg/`](../packaging/macos/dmg/README.md), and its volume is named `Local Sheets`
  without the version, which the window's background needs; the DMG file name keeps the version.
- **CLI:** the universal `localsheets-cli` is signed, zipped and notarized.

Locally, without certificates, the script signs ad-hoc (`codesign -s -`) and skips notarization:

```sh
packaging/macos/package.sh                    # universal; needs both rustup targets
packaging/macos/package.sh --arch aarch64     # quicker, host-only
open dist/release/localsheets-*-macos-*.dmg
```

### Windows

`packaging/windows/package.ps1 -Arch x64|x86|arm64` builds with `-C target-feature=+crt-static`
(no VC++ redistributable needed), checks both PE headers (machine matches `-Arch`; `localsheets.exe`
is GUI, `localsheets-cli.exe` console), signs both executables, builds two MSIs with WiX v5, signs
them, and zips a portable build.

- `localsheets.wxs`: one source, two packages selected with `-d Scope=perMachine|perUserOrMachine`
  (per-machine into `Program Files\Local Sheets`, `Program Files (x86)` for the 32-bit build;
  per-user into `%LOCALAPPDATA%\Programs\Local Sheets` with no UAC prompt; see
  `packaging/windows/INSTALLATION.md`). Each has a Start Menu shortcut, a `Sheets` alias shortcut
  for Start Menu search (every Local app name starts with Local, so searching "sheets" would
  otherwise find nothing) and a desktop shortcut, all plain links in their own components with an
  `HKMU` registry key path (ICE43). It registers App Paths (Win+R `localsheets`),
  `Software\Anon5T4R\LocalSheets\InstallDir` for the updater, and the file types: ProgIds
  `LocalSheets.Workbook` (`.xlsx`, `.xlsm`, `.xlsb`, `.ods`) and `LocalSheets.TextData` (`.csv`,
  `.tsv`), listed under each extension's `OpenWithProgids` and in `Capabilities` +
  `RegisteredApplications`, so Local Sheets appears in *Open with* and *Settings › Default apps*
  but never silently becomes the default. Local Sheets has no format of its own, so no ProgId
  carries a `<Verb>` (WIX0091 does not apply). The MSI version is the numeric `X.Y.Z`;
  same-version upgrades let release candidates replace each other.
- **Installer UI:** the standard WiX minimal UI (welcome + dual MIT/Apache license, progress,
  finish) with a ticked "Launch Local Sheets" on the finish page through `WixShellExec`; silent
  installs (`/qn`) never show it. `package.ps1` runs `wix msi validate -ice ICE50` for both MSIs
  before signing.
- **Portable zip:** written by hand with `System.IO.Compression.ZipArchive` (entry names with
  `/`), because `Compress-Archive` on PowerShell 5.1 writes `\` and the app's updater refuses those.
- **Signing:** `packaging/windows/sign.ps1` uses `signtool` with SHA-256 and an RFC 3161
  timestamp, from a `.pfx` (`WINDOWS_CERTIFICATE*`) if present, otherwise **Azure Trusted
  Signing** (`AZURE_*`). With neither it warns and leaves files unsigned.

Locally on Windows: `dotnet tool install -g wix --version 5.0.2`, then
`wix extension add -g WixToolset.UI.wixext/5.0.2`, `wix extension add -g WixToolset.Util.wixext/5.0.2`
and `pwsh packaging/windows/package.ps1 -Arch x64` (`-SkipBuild` re-packages existing binaries).

### Linux

`packaging/linux/package.sh` stages one FHS tree (both binaries,
`com.local.localsheets.desktop` with `MimeType=` for the four types, hicolor icons 16–512 px
+ scalable SVG, AppStream metainfo, shared-mime-info) and builds the AppImage (appimagetool),
`.deb` and `.rpm` (nfpm, `nfpm.yaml`) and `.tar.gz` from it. Built on Ubuntu 22.04, so the
binaries need glibc ≥ 2.35. X11/Wayland/xkbcommon/Vulkan/EGL are loaded at runtime; the
packages declare them (see `nfpm.yaml`).

Each AppImage embeds update information
(`gh-releases-zsync|Anon5T4R|local-sheets|latest|localsheets-*-linux-<arch>.AppImage.zsync`), and the
matching `.zsync` is published beside it, so AppImageUpdate and AppImageLauncher fetch only the
changed blocks of the newest published release. appimagetool writes the `.zsync` when
`zsyncmake` (the `zsync` package) is installed; without it the script warns and skips it.

Flatpak: `packaging/linux/flatpak/com.local.localsheets.yml` builds from source and is ready
for a Flathub submission (freedesktop 25.08; Wayland + X11 fallback, `dri`, IPC; Documents and
Downloads; everything else through portals); build it by hand with the commands in its header.
The single-file `.flatpak` comes from `packaging/linux/flatpak-bundle.sh` and
`com.local.localsheets.bundle.yml`, which repackage a Linux tarball (no Rust build) and
smoke-test the result in the sandbox.

Locally (on Linux): install [nfpm](https://nfpm.goreleaser.com/install/), then
`packaging/linux/package.sh` (or `--formats "deb tar"`).

### FreeBSD

GitHub has no FreeBSD runners, so there is no FreeBSD workflow. `packaging/freebsd/package.sh`
builds the release binaries on FreeBSD and writes `localsheets-<v>-freebsd-x86_64.tar.gz`
(`bin/` + `share/`, extract under `/usr/local`). No signing (checksums are in `SHA256SUMS.txt`).

### Web

`packaging/web/package.sh` runs `trunk build --release --dist dist/web --public-url ./` in
`apps/localsheets-web` and zips the site with sample `_headers` / `.htaccess` and the hosting guide
([`packaging/web/README.md`](../packaging/web/README.md)). Relative URLs only, so it works under
any path and in an iframe; the script fails on root-absolute URLs.

## Secrets

Every secret is optional: with one missing, that platform's artifacts are unsigned and the log
shows a `::warning::`. Configure them as repository (or environment) secrets:

| Secret | Used for |
|---|---|
| `AZURE_TENANT_ID`, `AZURE_CLIENT_ID`, `AZURE_CLIENT_SECRET` | service principal for Azure Trusted Signing |
| `AZURE_SIGNING_ENDPOINT` | e.g. `https://eus.codesigning.azure.net` |
| `AZURE_SIGNING_ACCOUNT`, `AZURE_CERT_PROFILE` | the signing account and certificate profile |
| `WINDOWS_CERTIFICATE`, `WINDOWS_CERTIFICATE_PASSWORD` | `.pfx` signing, when used instead of Azure |
| `APPLE_*`, `KEYCHAIN_PASSWORD` | only for a manual macOS run of `packaging/macos/package.sh`; no workflow job uses them today |

`GITHUB_TOKEN` publishes the release (`contents: write` on the publish job only).

## Icons

`assets/app-icon/localsheets.svg` is the master. `packaging/icons.sh` regenerates the 1024 px PNG,
the macOS 512 px PNG, the `.icns` (iconutil), the `.ico` (`cargo xtask ico`) and the hicolor PNGs
from it; it needs `resvg`. The outputs are committed, so packaging never needs those tools. Every
file has a row in `ATTRIBUTION.md` (`cargo xtask assets`).

## Checks

- `.github/workflows/ci.yml`, on every push to `main`/`master` and every PR, on Ubuntu 24.04 and
  Windows: `cargo fmt` over the workspace members only (nightly; `libs/` is vendored and keeps its
  upstream style), `cargo clippy --locked --all-targets -D warnings`, `cargo build --locked`, and
  `cargo test --locked --no-fail-fast` (serial on Windows, where the kittest UI tests collide in
  parallel). A second job rejects any `git+` source in `Cargo.lock`.
- `.github/workflows/release.yml`, on `v*` tags: the Windows and Linux packages above.
- Locally: `cargo xtask ci` (fmt, clippy, tests, doctests, assets, layers, wasm, parity, keytips),
  and `pwsh packaging/windows/package.ps1 -SkipBuild` after a release build to re-package.
